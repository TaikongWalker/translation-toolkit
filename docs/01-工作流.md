# 标准工作流

本流程适用于书籍（学术专著、非虚构、小说）与长篇文章。每本书都是独立项目，流程相同，严格程度按篇幅与出版要求调整。

---

## 0. 总原则

### 0.1 三个角色

| 角色 | 职责 | 谁来做 |
|---|---|---|
| 译者 | 初译、查证、术语提案 | 人 / AI 协作 |
| 审校 | 双语对照纠错、事实核查 | 第二遍（人或另一个模型） |
| 编辑 | 单语润色、体例统一、终校 | 第三遍 |

**关键要求：初译与审校不能是同一个“脑子”连续完成。** AI 辅助时，至少换一次会话/上下文，只拿原文+译文对照，不看初译时的推理过程。

### 0.2 四个“不”

- 不遗漏：原文的每一句、每一个脚注、每一幅图、每一张表都要有对应。
- 不增写：不替作者补充观点、不把隐含逻辑“讲明白”（除非加译者注并标明）。
- 不合并：不把两个脚注合成一个，不把图注并进正文。
- 不美化：不把模糊、反讽、口语、重复修得比原文“顺”；风格对等优先于文采。

### 0.3 状态机

每个翻译单元（章/节）经历：

```
未开始 → 初译 → 自校 → 双语审校 → 润色 → 排版 → 终检
```

状态记录在 `notes/progress.csv`。任何阶段回退，必须写明原因与日期。

## 1. 阶段 0：立项与原文抽取

**输入**：原文文件（EPUB / PDF / TXT / Markdown / HTML / DOCX / ODT / RTF / FB2 / MOBI / AZW3）、授权或使用范围说明、目标读者。

**动作**

1. 新建项目：
   ```powershell
   .\scripts\new-project.ps1 -Name <slug> -Title "<中文书名>" -Source "<原文路径>"
   ```
2. 若源文件为常见阅读文本格式，脚本自动抽取为 `source/*.md` 并生成 `source/manifest.csv`：
   - EPUB：内置后端，保留章节、脚注、图片、表格；
   - PDF：优先 MarkItDown，其次 pdftotext / PyMuPDF；扫描版需先 OCR；
   - TXT / Markdown：按标题、`第一章 / Chapter N` 或空行切分；
   - HTML / DOCX / ODT / RTF / FB2：内置后端，保留能识别的标题与脚注；
   - MOBI / AZW3：需 Calibre 的 `ebook-convert`，先转 EPUB。
3. 抽取结果先核对：章节数、图数、脚注数与原书是否一致；PDF 与 RTF 的脚注/图片可能丢失，需人工补查。
4. 填写 `project.json`：书名、副题、作者、译者、原书名、出版社、年份、语种、版权状态。
5. 在 `notes/decisions.md` 记录书名译法、作者译名等**重大命名决策**及理由。

**交付物**：`project.json`、`source/`、`source/manifest.csv`、`notes/decisions.md` 初始条目。

**门禁 G0：原文完整性核对**

- 章节数与目录一致；
- 图片数、脚注数、表格数与原文一致（`source/manifest.csv` 有统计）；
- 随机抽 3 页与原始文件比对，确认无乱码、无缺段、无错序。

> 注意：`source/` 是只读档案。任何清洗都在译文侧完成，不改原文。

## 2. 阶段 1：通读与背景卷宗

**目的**：先成为“懂这本书的人”，再动笔。逐句翻译而不懂全局，必然出现术语漂移、指代错误、语气失真。

**三遍阅读法**

1. **快读（结构）**：目录、序言、结论、每章首尾段。写出全书论证链。
2. **精读（内容）**：逐章读，标出核心概念、反复出现的隐喻、人物/机构、时间线、作者的态度（反讽？同情？论战对象？）。
3. **难点扫描（翻译）**：标出双关、文化专有项、长难句、引文、术语首次出现处。

**建立 `notes/context.md`**，必须包含：

- 书目信息与一句话主旨；
- 全书结构（部分—章—节）与论证推进；
- 逐章摘要（每章 3–5 句，含关键结论）；
- 核心概念表（原文—暂定译名—含义—首次出现）；
- 人物/机构/地名表（含俄文/英文原名、身份、关系）；
- 时间线与历史背景（尤其涉及制度转型、战争、政权更迭等）；
- 作者风格画像：句长、语域、修辞习惯、引文密度、幽默/反讽方式；
- 目标读者与翻译策略（学术读者？大众读者？是否保留外来语）；
- 风险清单（最可能译错/最难处理的 10 处）。

**门禁 G1：全局理解**

- 每章都有摘要；
- 核心概念 ≥ 20 条（长书 ≥ 50 条）；
- 作者风格画像能指导具体句式选择（不是“语言流畅”这种空话）；
- 风险清单已列，且每条有处理预案。

## 3. 阶段 2：术语提取与定名

**目的**：让全书的人名、地名、机构、作品、学术概念从第一页到最后一页完全一致。

### 3.1 生成候选

```powershell
python ..\..\scripts\term_candidates.py --project .
```

脚本从原文提取高频专名、斜体外来词、缩写，输出 `glossary/candidates.csv`。候选不是术语表，必须人工筛选。

### 3.2 分类

| category | 说明 | 示例 |
|---|---|---|
| 人名 | 真实人物、虚构人物 | Noam Chomsky → 诺姆·乔姆斯基 |
| 地名 | 国家、城市、街区、河流 | Paris → 巴黎 |
| 机构 | 政党、机关、学校、乐队、出版社 | UNESCO → 联合国教科文组织 |
| 作品 | 书名、文章、电影、歌曲、画作 | *The Wealth of Nations* → 《国富论》 |
| 术语 | 学术概念、行话、口号 | performativity → 述行性 |
| 其他 | 事件、族群、节日、物品 | Renaissance → 文艺复兴 |

### 3.3 查证顺序

1. 作者本人或该书已有中译本使用的译名（若有，优先沿用并在备注注明版本）；
2. 权威工具书：新华社《世界人名翻译大辞典》《世界地名翻译大辞典》、全国科学技术名词审定委员会「术语在线」；
3. 中文学界通行译法（Google Scholar / 知网检索“原文 + 译名”）；
4. 以上皆无：按“名从主人、约定俗成、音意兼顾”自拟，并在 `notes/decisions.md` 说明。

### 3.4 定名规则

- **人名**：姓名为“名·姓”，中文用间隔号；已有通行译名从通行（Trotsky → 托洛茨基，不译“特罗茨基”）。首次出现可括注原文。
- **地名**：用标准译名；非通用小地名音译，首次括注原文。
- **机构**：用通行简称；首次出现给全称，缩写用“中文全称（英文缩写）”。
- **术语**：同一概念全书只用一个译名；确需并用的，在术语表用 `/` 标明并规定使用场景。
- **作品**：书名号《》；原文书名首次出现括注，之后只用中文。
- **外来语**：原文中的俄语/德语等斜体词，译文首次出现给“中文（原文转写）”，之后用中文；若该词本身是分析对象（如 *habitus*、*Gemeinschaft*），保留原文并加译者注。
- **缩写**：首次出现“中文全称（English Full Name, ABC）”，之后用缩写。

### 3.5 术语表字段（`glossary/terms.csv`）

```csv
source,target,category,status,notes,forbidden,first_seen
habitus,惯习,术语,final,布尔迪厄用语；首次出现括注原文,习惯,ch01
performativity,述行性,术语,final,Austin 用语；作者核心概念，保留原文并注,表演性|施为性,ch02
```

- `status`：`draft` / `final` / `deprecated`。`draft` 条目会进入术语表并标注“（暂定）”，定名后改 `final` 即去掉标记；`deprecated` 不进入成书。
- `forbidden`：禁止使用的变体，用 `|` 分隔；`check.py` 会扫描译文
- 一个 source 一行；同一原文多义项时分行并在 notes 说明语境

**门禁 G2：术语冻结 v1**

- 前 3 章出现的专名 100% 有定名；
- 核心术语（作者反复使用的概念）100% 有定名；
- 禁止变体已登记；
- 术语表通过 `python scripts/prepare.py --project .` 能正常生成对照表。

## 4. 阶段 3：试译校准

选 **1500–2500 字** 代表性段落，必须覆盖：

- 术语密集段；
- 含脚注/引文的段落；
- 含长难句或修辞的段落；
- 对话或口语（若有）。

**产出**

- `chapters/ch00-pilot.tex`（或并入第一章，标记“试译”）；
- `notes/style.md`：句长偏好、四字格使用限度、外来语处理、引号体例、注释体例、称呼与语气；
- 术语表修订记录。

**门禁 G3：风格确认**

- 双语审校 + 单语润色各一遍；
- 与原文对照朗读，确认“像中文书，而不是翻译腔”；
- 风格表能落成可执行的规则（例：“学术长句拆为 2–3 个中文短句，但保留原文的限定语层级”）。

## 5. 阶段 4：分章初译

**操作顺序（每章）**

1. 先通读整章（不查词），确认本章在全书中的功能；
2. 建本章术语清单，对照 `terms.csv`；缺的先补表；
3. 逐段翻译，保持段落与原文一一对应（段落数可微调，但不得整段合并/拆分而不留痕）；
4. 脚注、图注、表格就地完成，不留“待补”；
5. 不确定处标 `%% TODO: 原因`，不要凭感觉硬译；
6. 译完立即自校一遍：对照原文查漏句、查数字、查专名。

**文件约定**

- 一章一个文件：`chapters/ch01.tex`、`ch02.tex`……；前言、结论、附录分别建文件；
- 章节文件只写正文，不写 `\documentclass`；
- 标题用 `\chapter{}` / `\section{}`，不要在正文手写“第一章”。

**每章完成标准**

- 段落/脚注/图数量与原文核对（`check.py` 会报差异）；
- 无 `TODO` 遗留，或已在 `notes/progress.csv` 登记；
- 术语表已更新。

---

## 6. 阶段 5：双语审校（准确性）

**方法**：以句/段为单位对照，不看初译理由，只问四个问题：

1. 这句话原文到底说了什么？译文有没有多、少、反、偏？
2. 逻辑连接（因果、转折、让步、限定）是否保留？
3. 指代（this / it / they / 上述）是否指向同一对象？
4. 数字、日期、人名、引文、注释编号是否准确？

**必查清单**

- [ ] 否定与双重否定
- [ ] 时态/体（尤其俄语过去时的完成/未完成体转写为中文时）
- [ ] 情态（may / might / must / supposedly / 据说）
- [ ] 引语边界与说话人
- [ ] 讽刺与反话（是否被译成字面意思）
- [ ] 文化专有项（是否过度归化）
- [ ] 脚注与正文的对应关系
- [ ] 图表编号与正文引用
- [ ] 参考文献条目（若翻译）

**产出**：`notes/review-ch01.md`（问题列表：位置 / 原文 / 初译 / 问题类型 / 改译），修订后的 tex。

**门禁 G4**：A 类错误（漏译、反义、事实错误、数字错误）为零；B 类（搭配、指代、逻辑）已处理或登记。

---

## 7. 阶段 6：单语润色（风格）

**方法**：遮住原文，只读中文。逐段问：

- 这句话中文里有人会这样说吗？
- 长句是否该拆？短句是否该并？（允许句法重组，信息量不变）
- 是否有“的的不休”、被动泛滥、名词化堆叠、连接词冗余？
- 作者的语气（冷静/讥讽/热情/克制）还在吗？
- 术语是否刺眼地重复？重复是原文特征还是翻译懒惰？

**朗读测试**：每章至少朗读一遍，标记读不顺的地方。

**禁止**：借润色之名删信息、改观点、加文采。

---

## 8. 阶段 7：排版与终检

```powershell
.\scripts\build.ps1 -Project . -Open
```

流程：生成元信息/术语表 → `latexmk -xelatex` 编译 → 自动检查 → 输出 `dist/<slug>.pdf`。

**自动检查**（`scripts/check.py`）

- 术语：原文残留、禁用变体、术语未使用；
- 标点：中文旁的半角标点、英文引号、`...`、`--`；
- 结构：每章脚注数/图数与原文对照；
- 内容：长段未翻译英文、`TODO` 计数。

**人工终检（看 PDF，不看 tex）**

- [ ] 封面、书名页、版权页、目录、正文、附录、术语表齐全
- [ ] 目录页码正确，标题层级正确
- [ ] 页眉书名/章名正确，奇偶页方向正确
- [ ] 脚注编号连续，未被排版吞掉，跨页正常
- [ ] 每幅图清晰、位置合理、图注与正文引用一致
- [ ] 表格不溢出，长表跨页有表头
- [ ] 引文缩进/字体与正文区分
- [ ] 无孤行、孤字（至少目视检查）
- [ ] 随机抽 10 页与原文对照，确认排版未造成内容丢失

**门禁 G6**：自动检查无 A 类问题；人工终检清单全部通过；PDF 元数据正确。

---

## 9. 阶段 8：交付与归档

**交付物**

```
dist/<slug>.pdf              最终 PDF
main.tex + chapters/         可继续修订的 LaTeX 源
glossary/terms.csv           术语库
notes/context.md             背景卷宗
notes/decisions.md           命名与重大决策记录
notes/progress.csv           进度与状态
source/                      原文档案（只读）
```

**版本**：在 `project.json` 的 `version` 字段递增（0.1 初译 → 0.9 校样 → 1.0 定稿）；重大修订在 `notes/decisions.md` 记日期与原因。

**归档**：整个项目目录打包；不要只留 PDF，否则后续修订成本极高。

## 10. 质量门总表

| 门 | 时机 | 通过标准 | 不通过怎么办 |
|---|---|---|---|
| G0 | 抽取后 | 章节/图/脚注数一致 | 修提取脚本或换源文件 |
| G1 | 通读后 | 卷宗完整、风险清单成立 | 补读，不进入翻译 |
| G2 | 术语后 | 核心词全定名、变体登记 | 继续查证，不试译 |
| G3 | 试译后 | 双审通过、风格表可执行 | 调整策略，重试译 |
| G4 | 每章审校后 | A 类错误为零 | 返工该章 |
| G5 | 润色后 | 朗读通过、无翻译腔 | 继续润色 |
| G6 | 终检后 | 自动+人工全通过 | 修复后重新构建 |

---

## 11. 批量与节奏建议

- **每天开工前**：读一遍 `notes/context.md` 的本章摘要与风格表；跑一次 `check.py` 看昨天是否引入不一致。
- **每章结束**：更新术语表、进度表、决策记录；提交一次版本（若用 git）。
- **每 3–5 章**：回读已译章节的开头，检查语气是否漂移。
- **全书 30% / 70%**：各做一次全局术语扫描与风格校准。
- **不要边译边精修**：初译求“全”，审校求“准”，润色求“顺”，三件事分开做，效率与质量都更高。
